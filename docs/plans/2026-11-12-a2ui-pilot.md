# A2UI lead-review pilot

## Design and acceptance

The owner requested the proposed website pilot now. Add `/demo/ai` to the existing fictional staff demo, using the official A2UI React renderer and protocol 1.0. Keep the established AgencyDesk design language and responsive app shell. A visible sample-data notice explains that responses are prebuilt locally: there is no connected model, customer data, API request, persistence or send operation.

The page starts with open sample leads, offers three prompt-like presets (open leads, proposal follow-ups, closed leads), and lets a user inspect a lead in an inline detail surface. An explicit reset restores the initial response. Unsupported input/actions fail closed. Mobile keyboard navigation, accessibility, error recovery and absence of mutating network requests are acceptance cases. The pilot must be reachable from demo navigation, never live CRM navigation. Existing homepage work stays untouched and unpublished.

Approaches considered: (1) a dedicated A2UI demo surface, selected here because it demonstrates the real renderer without changing existing customer flows; (2) replacing the public service assistant, deferred because that assistant has different data/intent; (3) connecting a live model and CRM, deferred until the rendering and approval boundaries are proven. These implementation choices are the builder's calls within the authorized pilot.

## Implementation plan

**Goal:** Deliver a free, local-only A2UI website pilot for fictional lead review.
**Architecture:** Pure fixture-to-protocol builder plus an isolated React renderer with a small allowlisted custom catalog. Local actions rebuild a bounded surface; no remote tools or arbitrary HTML, URLs, code or schema fetching.
**Stack:** Next.js 16.3.8, React 19.2.8, TypeScript, CSS modules, `@a2ui/react` and `@a2ui/web_core` pinned to 0.15.0. Catalog schemas use the exact Zod 3.25.76 through `zod-a2ui`; the application keeps Zod 4.6.5. A narrow `.pnpmfile.cjs` hook removes this renderer release's duplicate Zod peer so pnpm 10 keeps its declared Zod 3 dependency. The renderer and catalog are dynamically loaded with `ssr:false`, because the SDK registers browser custom elements and cannot run during SSR.
**Execution:** Inline, one independent final code/security reviewer per AgencyDesk rules.

## Review focus

Unknown preset/lead/action cannot fall through to a privileged operation. Malformed protocol output produces a recoverable error. Rendering sessions do not leak between requests. The new runtime is confined to the demo route. Repeated actions/reset preserve accessible state and cannot create remote side effects.
